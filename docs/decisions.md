# Decisions

Versioned record of product and architecture decisions. Append; do not rewrite history.
Superseded decisions are marked, not deleted.

|---|---|---|---|
| D-001 | 2026-10-20 | Keep the brief's stack: Next.js + TypeScript, FastAPI + Pydantic, PostgreSQL, Docker Compose. | Participant direction; supports later research workflow. Single-server SQLite proposal rejected. |
| D-002 | 2026-10-20 | No job queue or worker in Milestones 1–2. Parsing runs synchronously in the upload request inside one transaction. `services/worker` is a placeholder. | Files are small and parsing is deterministic. | D-003 | 2026-10-20 | One seeded participant (`00000000-…-0001`). All rows carry `participant_id`. No multi-user features. | Brief: no multi-user. Keeps the schema ready for clinician-supported use later without building it now. |
| D-004 | 2026-10-20 | **Revision to Milestone 1:** user authentication deferred for the local-only build. Authentication and a deployment security review remain prerequisites for any remote or LAN access. |
| D-005 | 2026-10-20 | Disk encryption is a host requirement (FileVault). The app does not claim at-rest encryption. Backups are optionally encrypted via `CARDIO_BACKUP_PASSPHRASE_FILE`. | Honest scope. Backup encryption is tested in `make restore-test`. |
| D-006 | 2026-10-20 | PREVENT licensing and access to authoritative reference outputs are unresolved **Milestone 3 dependencies**. Not implemented; does not block M1–2. | AHA distributes source under license; Gate B needs reference outputs. |
| D-007 | 2026-10-20 | Fixtures are synthetic, generic layouts. No Function Health or other vendor compatibility is claimed. Testing an actual redacted report is an outstanding ingestion-validation step. | No real report has been reviewed. |
| D-008 | 2026-10-20 | Immutability is enforced by database triggers: observation values/provenance immutable; rejected/superseded terminal; audit append-only; deletes refused. | Application bugs or ad-hoc SQL cannot silently rewrite the record. Tested directly with SQL. |
| D-009 | 2026-10-20 | `extraction_status` and `verification_status` are separate columns. Acceptance requires `confirm_source_matches=true`, no blocking issues, and no open flags. | Brief §5: extraction creates candidates, not facts. |
| D-010 | 2026-10-20 | Normalization keeps original text beside normalized values. Test-name dictionary covers 14 analytes; unrecognized names stay unrecognized (warning, not blocker) and can be mapped by the participant. | Unknown stays unknown. |
| D-011 | 2026-10-20 | No unit conversion. `normalized_unit` is a canonical spelling of the reported unit; different units form separate series. Lp(a) mass and molar are never merged. | Brief §5 (EAS guidance on Lp(a) conversion). Conversions require a recorded, tested rule per analyte. |
| D-012 | 2026-10-20 | Numeric dates with both parts ≤12 and differing are ambiguous unless the participant declares the document's date order at upload. Two-digit years are ambiguous. Participant resolutions are recorded as `participant_resolved`. | Never guess dates. |
| D-013 | 2026-10-20 | Collection method (venous/capillary/unknown) is separate from specimen type. "Serum"/"plasma" alone does not establish venous collection. Basis recorded: stated in source, declared at upload, participant-entered, unknown. | Keeps capillary/venous streams honest. |
| D-014 | 2026-10-20 | Duplicate, conflicting-value and lab-correction candidates are flagged, never merged. Capillary vs venous on the same day are not flagged as duplicates. Accepted observations involved in an open flag are withheld from calculation inputs. | Brief §5; conflicts are unresolved uncertainty. |
| D-015 | 2026-10-20 | The only calculation-input interface is `app/calc_inputs.py` (HTTP: `GET /api/v1/calculation-inputs/observations`): accepted, `verified_at` set, no open flag. | Single boundary to test; double guard (status + timestamp) shown by mutation check. |
| D-016 | 2026-10-20 | Accepted observations may be withdrawn (→ rejected) with a reason. Rejected and superseded are terminal; re-entry is a new observation. | Allows retracting a mistaken acceptance without deleting history. |
| D-017 | 2026-10-20 | Unhandled errors are caught by `SafeErrorMiddleware` and logged as type + code location only. | Starlette's default handler re-raises and the server logs exception messages, which can contain values. |
| D-018 | 2026-10-20 | Browser talks only to Next.js; `/api/*` is proxied to FastAPI. `API_INTERNAL_URL` is fixed at build time. | Single origin, no CORS needed. |
| D-019 | 2026-10-20 | Timestamps default to `clock_timestamp()` and all list queries have an id tie-breaker. | Found by the restore test: rows created in one transaction shared `now()`, making list order nondeterministic. |
| D-020 | 2026-10-20 | Original PDFs are served inline without a sandbox CSP (so the browser PDF viewer works); other formats are sandboxed attachments. | Chrome blocks its PDF viewer under `CSP: sandbox`. |
| D-021 | 2026-10-20 | On correction, interpretations the participant supplied (resolved dates, test mapping, specimen type, collection method) carry forward unless the correction changes them or their source text. | A later unrelated correction must not undo earlier resolutions. |
| D-022 | 2026-10-20 | Test isolation: pytest refuses any database not named `cardio_test`; e2e and restore tests run in separate Compose projects with their own volumes and ports. | Tests never touch development or real data. |
| D-023 | 2026-10-20 | `docs/product-brief.md` is the brief verbatim (only a leading `#` added to the title). | Preserves the founding document unedited. |
| D-024 | 2026-10-21 | **Rule SPEC-1:** a known specimen type outside the analyte's consistent matrices (`vocab.CONSISTENT_MATRICES`; HbA1c: whole blood or dried blood spot; lipids/apoB/Lp(a)/hs-CRP/insulin: serum, plasma, whole blood, DBS) is a blocking `specimen_conflict`. The stated value is kept verbatim and never rewritten to the expected matrix. Resolution is a correction: set the specimen type to `unknown`, or a deliberate participant choice (audited, exempt from the rule). | Overnight queue 1A. Regression: HbA1c under a "Specimen: Serum" report header. The table is deliberately small; extending it is a recorded decision, not a dictionary sweep. |
| D-025 | 2026-10-21 | `specimen_source` (row / report_header / participant_entered / none / not_recorded) and `inherited_metadata` (verbatim header text and page per inherited field) are stored per observation (migration 0002). Collection method and specimen matrix stay separate: "Venipuncture" never implies serum or plasma. | Distinguish explicit row metadata from inherited or uncertain metadata. |
| D-026 | 2026-10-21 | Duplicate and correction candidates use collection-event context. Accession/specimen IDs are captured from CSV columns and PDF headers. Both present and different means a different collection event: no flag. Same accession is a strong match. Otherwise the flag records a weak `match_basis` (same laboratory and date, or date and test only). Flags never merge. | Overnight queue 1B: value-only matching is insufficient, and date+test must not merge legitimate repeats. |
| D-027 | 2026-10-21 | The calculation boundary additionally excludes rows carrying any blocking extraction issue and rows that have any successor version, even if status says accepted. | Defense in depth: an observation and its accepted replacement can never both be counted. Tested by bypassing the app with SQL. |
| D-028 | 2026-10-21 | Destructive test operations go through `scripts/lib/disposable.sh`: the Compose project must match `^cardio-(test\|e2e\|restore-test\|clean)$`, must not be the working project (`cardio`), must resolve to that name in `docker compose config`, and the volumes deleted must carry that project's label and prefix. `make test` now runs in project `cardio-test` (its own Postgres). `restore.sh` refuses non-disposable targets when `CARDIO_RESTORE_TEST=1`. pytest also refuses a document root outside `/tmp/`. | Overnight queue 1C. Verified with `make guard-test` without running any destructive command against the working app. |
| D-029 | 2026-10-21 | Evidence records, research questions, chart specs and build notes are versioned JSON files under `research/` with one shared schema (`packages/evidence-tools`). No database tables, vector store or agent fleet. | Smallest format that serves both the public notebook and the future research layer; reviewable as diffs. |
| D-030 | 2026-10-21 | Source fidelity is machine-checked: every reported number, at its reported precision, must appear in the claim's verbatim quote; with the out-of-repo full-text cache, every quote must appear verbatim in the source; derived numbers are recomputed; chart CSVs must equal the rows regenerated from spec + claims. | Prevents drift between charts, records and sources. The full texts are not committed (copyright); the cache lives outside the repo. |
| D-031 | 2026-10-21 | Personal applicability is a separate field and must be `not_assessed` while `PERSONAL_RECORDS_IMPORTED = False` (validator and notebook build both enforce it). | No personal records are imported; research findings must not read as personal findings. |
| D-032 | 2026-10-21 | The notebook (`apps/notebook`) is a separate Next.js app, statically generated from `research/` at build time, on loopback port 3100. It has no API proxy, no database connection and no access to private documents. Publication status cannot be `published`; nothing is deployed or pushed. | Keeps the public notebook structurally separate from private health records. Tested: records API paths return 404 on the notebook. |
| D-033 | 2026-10-21 | Charts show only values stated in the text or tables. Bars or points visible only in figure images are not reconstructed (e.g. Sniderman Figure 2 bars other than the three quoted pairs). Units that the paper does not state are labelled as not stated. | Do not invent or reconstruct unsupported data. |
| D-034 | 2026-10-21 | The system will not compute a single "cumulative LDL-C" (or similar exposure) number from sparse personal records without stating every interpolation assumption, and never treats a study's quartile cutoffs as personal thresholds. | Research entry B; historical records establish measured points, not unmeasured years. Binding on Milestone 3+ work. |
| D-035 | 2026-10-21 | Review status `source_verified` means an automated agent matched values to sources and the validator passed. An additional automated reviewer agent may challenge entries; neither counts as independent or clinical review (`independent_review: false`). | Honest labelling of review depth. |
| D-036 | 2026-10-21 | PDF parser v2 (v4: reference text starting inside the out-of-range column is folded into the reference, not read as a second result; v5: the comment-indent cutoff is 30pt, so sub-results indented ~21pt are kept; v3: reference ranges printed inside the result column are split off; margin-aligned running text with more than three words in a result cell is skipped as a comment) reads range-split tables ("Test Name / In Range / Out of Range / Reference Range / Lab"). The result is whichever range cell is filled (both filled: row skipped for manual entry); a trailing H/L in the out-of-range cell is the laboratory flag; the unit is taken from the reference cell after the range, with any trailing qualifier such as "(calc)" kept as the method; a "Previous Result (and Date)" column is recognised only so it is never read as the result; panel heading lines carrying "Collected:" set the collection date for their rows, and a new collection date drops earlier fasting status; lines indented under the test-name column are comments. | First real-report import (three reports, structure inspected with all values masked): no result column was recognised, and in one variant the "Result" in "Previous Result" was taken as the value column. Fixed against synthetic reproductions of the structure only. No candidate from the misparsed import could have been accepted: all carried blocking issues. |
| D-037 | 2026-10-21 | A stored document can be re-extracted with the current parser while none of its candidates has been accepted or corrected. Earlier unreviewed candidates are rejected with an audited reason ("Replaced by re-extraction…") and hidden from document counts, never deleted; the date-order declaration may be set at the same time (audited). | Parser fixes must reach already-uploaded originals without re-uploading (which would create duplicate documents) and without breaking append-only history. |
| D-038 | 2026-10-21 | **Automated acceptance (participant decision, revises the explicit-review rule).** `POST /documents/{id}/auto-accept` first sets aside results printed twice in the same report (same test, value, unit and date: the later printing is rejected with a reason), then accepts every remaining candidate that has no blocking issue, a numeric value, value and unit found verbatim in its source line, and no open flag. Every acceptance records `verification_method` (`participant_review` or `automated_check`, migration 0003, set once and enforced by the update trigger); the calculation boundary requires it and returns it, so downstream work can always tell automated from reviewed values. Rows failing any check stay unverified. | The participant declined to review ~440 rows by hand. Automated checks verify transcription from the source line, not clinical correctness; the label keeps that distinction visible. |
| D-039 | 2026-10-21 | Previous results reprinted by a later report are imported as separate observations labelled `reported_as = historical_in_later_report` (parser v6, migration 0004), dated by the date printed with them, with no accession or reference range (none is stated). When one matches the original report's own result (same test, date, value, unit) it is set aside as corroboration, never counted twice. | Personal Baseline queue 1: distinguish historical from current measurements; reprints are evidence about the original, not new measurements. |
| D-040 | 2026-10-21 | A participant can confirm an automated-check acceptance against the source (`POST /observations/{id}/confirm`), changing `verification_method` once, from `automated_check` to `participant_review` (trigger-enforced, audited). Re-extraction may withdraw automated acceptances but never a participant review. | Queue 1: AI- or software-checked values are not "verified" by a person; the existing source-review workflow provides the confirmation path. |
| D-041 | 2026-10-21 | **Research runtime v0.1** (`services/api/app/research/runtime.py`): deterministic rules inside the API, no language model, no external provider. Inputs only from the calculation boundary; each snapshot (`research_snapshots`, append-only, versioned) stores copied inputs with their verification method, the rules file's SHA-256 and the outputs. Findings carry exact observations with source document and page, what they establish and do not, comparability, ledger evidence by claim ID (or an explicit evidence gap), competing explanations, distinguishing information and the decision affected; findings resting on unconfirmed observations are marked provisional. At most five; conventional results are summarised, not investigated. | Queue 2-3: the investigation must run in the application, be reproducible, and not manufacture findings. |
| D-042 | 2026-10-21 | Cohort intervals quoted in the ledger are compared with personal values only within 5 mg/dL of the quoted anchor and never interpolated; the margin to the bound is always stated. | The first real run compared LDL-C 78-79 with the interval quoted at 70 and reported a 1 mg/dL "discordance"; that was an artefact of the rule, removed before reporting. |
| D-043 | 2026-10-21 | Result types (`quantity`, `dimensionless`, `categorical`, `bounded`, `text`; migration 0005). The acceptance constraint is type-aware. | Discrepancy queue 2: do not force results into number-plus-unit or convert <10 into 10. |
| D-044 | 2026-10-21 | Parser v7-v8: wrapped test names in range-split tables are joined to the adjacent result (both source lines kept, warning issue); indented comment lines are kept with their result; "Accession <id>" without a colon is captured. | Discrepancy queue 2: fix wrapped names without discarding source text; report identifiers for source review. |
| D-045 | 2026-10-21 | Identical results under two accession identifiers in one document are flagged `same_document_different_accession` and the later printing is set aside, never merged; whether the two identifiers are one specimen is a participant verification item. | D-046 | 2026-10-21 | Research runtime v0.2 adds a provider-backed workflow (snapshot -> question -> evidence -> applicability -> competing explanations -> interpretation) beside the preserved v0.1 rules.
